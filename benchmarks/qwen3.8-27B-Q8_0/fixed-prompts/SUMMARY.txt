oracle-select: the temp-0 answer plus 5 samples (t0.6, top_p 0.95, top_k 20). The model
writes a differential test against the REAL stdlib function (edge cases + 300 seeded
random inputs, prints `MISMATCHES n OF total`). Candidates are ranked by that count,
then up to 8 fix rounds hill-climb on it, keeping the version with fewest mismatches.
Hidden checks are never used for selection; an answer importing the reference module
is voided.

oracle-select v2 -- is fixing the test legitimate? Only if the test is graded by
something other than the candidate. v2 grades it by the stdlib: the real function is
substituted for the candidate and the test must report MISMATCHES 0 over 300+ cases
(up to 3 test fixes, then up to 2 fresh tests at t0.6). If no test passes, the greedy
answer is kept with no ranking and no repair. During repair a rewritten test is accepted
only if the stdlib still passes it with no fewer cases. add_months has no stdlib function
and stays unvalidated (its only reference is the benchmark's own, which is off limits).
Run against v1's saved tests, the check rejects textwrap's crashing test and parse_qsl's
first test and accepts the rest.
An aborted first v2 run (superseded/oracle-select-v2-aborted*) showed why "never use an
invalid test" matters: glob's test called fnmatchcase(pattern, name) with arguments
swapped, survived 3 fixes, and the climb bent a correct answer toward it (lost `class`).
